## Stagger → Trigger bridge

- probabilistic/unopposed coin execution now detects a newly-created Stagger transition immediately after the causing coin.
- branch-local `after_stagger` Trigger rules can change state before the next coin/action.
- legacy passive trigger name `Stagger` is also supported.
- queued follow-up actions generated by a Stagger trigger execute in the same probability branch.
- existing `after_coin` / `after_skill` trigger flow remains intact.
- Stagger is detected from either `stagger_level` or `stagger_index` increase, covering threshold transitions.
