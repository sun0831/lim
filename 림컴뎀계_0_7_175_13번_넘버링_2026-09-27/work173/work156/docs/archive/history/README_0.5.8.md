# 림컴뎀계 0.5.8

## 목적

0.5.7의 범용 Trigger/ActionQueue 구조를 기반으로, 현재 인격 카탈로그에서 **1턴 계산에 영향을 줄 가능성이 높은 미구현/부분 구현 패시브와 특수기믹을 자동 추출**한다.

## 추가 파일

- `gimmick_gap_analyzer_v1.py` : 카탈로그 패시브를 다시 컴파일하고 미지원/부분 구현 항목을 추출
- `gimmick_gap_report_v1.json` : 588개 패시브 레코드의 상태 및 원문/분류 데이터
- `GIMMICK_GAP_REPORT_v1.md` : 구현 우선순위 검토용 사람이 읽는 보고서

## 현재 분석 결과

- 인격: 184
- 패시브 레코드: 588
- 완전 컴파일: 193
- 부분 컴파일: 156
- 완전 미지원: 239
- 부분/미지원 합계: 395

### 미지원 요소 유형

- trigger: 543 clause-level 발생
- effect: 408 clause-level 발생

`trigger/effect` 수치는 패시브 레코드 수가 아니라 clause-level 미지원 발생 횟수이며, 하나의 패시브에서 여러 번 집계될 수 있다.

## 중요 주의

이 보고서의 `full`은 **문자열 컴파일러가 모든 clause를 현재 지원된 Effect/Trigger로 변환했다는 의미**다. 실제 게임과의 완전한 동작 일치를 의미하지 않는다.

반대로 `partial/unsupported`도 단순히 “당장 데미지 계산이 불가능하다”는 의미는 아니다. 일부는 생존/턴 종료/타겟 선택 등의 비데미지 효과이고, 일부는 향후 전투 상태 머신에 필요한 기초 기능이다.

## 구현 우선순위

보고서는 다음 항목을 우선 탐색한다.

1. 스킬 변형/강화/추가 공격/일방 공격
2. 공격 시작/적중/공격 종료/흐트러짐 등 전투 중 Trigger
3. 충전/탄환/호흡/특수 자원의 소모·획득·변환
4. 다른 인격과의 연계/보조공격
5. 특정 아군/적 선택 및 무작위 대상
6. E.G.O/패닉/침식/보호막/초근성 등 특수 상태
7. 확률/랜덤 분기

## 다음 구현 방향

우선순위가 높은 항목을 하나씩 `TriggerRule` 데이터로 전환하고, 실제 실행은 기존 `ActionQueue`와 연결한다.

특히 다음 형태를 표준화한다.

`Event → Condition → Effect → TriggeredAction/StateChange → Resolve next action`

이렇게 하면 새벽사무소 같은 특정 진영을 하드코딩하지 않고 다른 인격의 연계/흐트러짐 파생/자원 임계값에 의한 스킬 변형에도 같은 엔진을 사용할 수 있다.
