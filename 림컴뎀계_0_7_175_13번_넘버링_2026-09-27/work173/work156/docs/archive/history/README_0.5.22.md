# 림컴뎀계 0.5.22

## 합(Clash) 교환 상태 추적 보강

이번 버전은 사용자가 정의한 **각 합 과정에서 적이 실제로 굴린 코인 수**를 별도 상태 계층으로 추적한다.

### 핵심 규칙

- 합 횟수는 아군/적 스킬의 명목상 코인 수와 동일하다고 가정하지 않는다.
- 각 합 교환 시작 시 `defender_coins_rolled`를 기록한다.
- `defender_coins_rolled = 해당 합 시작 시 적의 남은 코인 수`.
- `W`(아군 합 승리) → 적 코인 1개 감소.
- `L`(아군 합 패배) → 적 코인 유지.
- 해당 합에서 발생하는 출혈 발동 횟수는 `defender_coins_rolled`와 같다.
- 적 코인이 0이 되면 `unopposed_after=true`로 기록한다.

### 사용자 지정 합 입력

행동의 `clash`에 다음을 추가할 수 있다.

```json
{
  "skill_power": 5,
  "coins": [{"coin_power": 1}, {"coin_power": 1}, {"coin_power": 1}],
  "initial_attacker_coins": 3,
  "initial_defender_coins": 3,
  "exchange_outcomes": ["W", "W", "L", "L", "L"]
}
```

그러면 적 코인 추적은:

`3 → 2 → 1 → 1 → 1`

출혈 발동 횟수는:

`3 + 2 + 1 + 1 + 1 = 8`

로 기록된다.

`attacker_coins_after`를 교환별로 지정하면 명목상 스킬 코인 수보다 많은 합 교환도 표현할 수 있다. 이는 실제 게임 규칙을 추측해서 강제로 제한하지 않기 위한 입력 계층이다.

### 결과

각 행동의 `clash_trace`에 다음이 들어간다.

- 합 번호
- 합 결과
- 합 시작 적 코인 수
- 해당 합에서 적이 굴린 코인 수
- 합 종료 적 코인 수
- 해당 합 출혈 발동 횟수
- 아군 코인 상태(입력된 경우)
- 일방 공격 전환 여부
- 전체 합 횟수
- 전체 출혈 발동 횟수

또한 `event_log`에 `clash_exchange`와 `bleed_proc_batch`를 남긴다.

## 주의

이번 계층은 **합/상태이상 발동 횟수 추적을 먼저 정확하게 분리**한 것이다. 기존 전투 엔진의 실제 합 위력 판정과 사용자 지정 교환 추적을 아직 동일한 판정기로 강제 결합하지 않았다. 검증되지 않은 게임 규칙을 임의로 만들어내지 않기 위한 설계다.
