# 0.7.67 실제 원문 → 계산기 기믹 정합성 감사

## 감사 목적
`identity_catalog_v2.json`에 실제 기재된 전투 기믹이 현재 1턴 계산기 구조에 **의미적으로 적절하게 반영되어 있는지** 확인한다.

판정은 다음 4단계로 한다.
- 🟢 완전 반영: 원문 의미가 계산 실행 경로까지 연결됨을 확인
- 🟡 부분 반영: 일부 조건/대상/효과만 표현되거나 Compiler/Runtime 한쪽만 지원
- 🔴 미반영: 원문은 있으나 현재 계산 경로에서 의미를 실행할 수 없음
- ⚪ 범위외: 1턴 계산기의 전투 계산 대상이 아닌 정보

## 핵심 발견
현재 Target Selector의 기본 축은 상당 부분 존재하지만, 원문 기믹 전체를 계산기에 반영했다고 볼 수 없다.
특히 실제 원문에서 반복되는 `필터 → 우선순위 → 순위 → 수량` 복합 대상 지정과 `추가 행동/자원변환/스킬변환/확률/다른 인격 연계`가 큰 미완성 영역이다.

## 현재 구조에서 확인된 🟢/🟡 영역
### 🟢 기본 Target 축
- 속도 최댓값/최솟값
- 현재 HP 최댓값/최솟값
- HP 비율 최댓값/최솟값
- 최대 HP 최댓값/최솟값
- 편성 순서 최댓값/최솟값
- 특정 편성 슬롯
- 상대적 편성 순서
- 충전 보유자 중 충전 최솟값
- 호흡 위력 최댓값/최솟값
- 호흡 횟수 최솟값
- 진동 횟수 최댓값/최솟값

- 상태 보유자 중 정신력 최솟값

### 🟡 부분 반영
- 정신력 최댓값/최솟값: 기본 순위는 있으나 `더하기 코인 우선`, `패닉/침식 제외` 같은 추가 eligibility/priority는 별도 처리 필요
- 충전 최댓값/최솟값: Runtime은 기본 축을 처리하지만 일부 원문 복합조건은 미연결
- 탄환 최댓값/최솟값: Runtime의 기본 값 축은 있으나 Compiler의 원문 승격이 일부 누락되어 있었음
- 무작위 대상: 기본 random은 있으나 `필터된 집합에서 random`, `우선 집합 → random`, `자신 제외` 등의 복합형은 별도 표현 필요
- 편성순서: 절대/상대 순위는 있으나 소속/상태 필터와 결합된 복합형이 부분 지원

## 🔴 주요 미반영/부분 구현 축
1. **필터 + 순위 조합의 일반화 부족**
   - 예: `N사 광신도 중 정신력이 가장 낮은 아군`
   - 예: `자신보다 편성 순서가 빠른 아군 중 충전 횟수가 낮은 아군`
   - 일부는 개별 Selector로 승격했지만 범용 Filter → Rank 구조는 아직 부족.

2. **Priority / fallback**
   - 원문: `더하기 코인을 사용하는 인격에게 우선`
   - 원문: `검지 소속 인격이 있으면 해당 인격에게 우선`
   - 원문: `대기 해제된 인격 우선, 그 다음 편성 순서`
   - 단순 min/max로 표현하면 원문의 우선순위 의미가 사라진다.

3. **복합 Random**
   - `특정 조건을 만족하는 대상 중 무작위`
   - `특정 소속 우선 후 무작위`
   - `자신 제외 무작위`
   - `최대 N명` + 조건부 인원 증가

4. **추가 행동/강제 행동**
   - 원문에는 `특정 인격이 특정 조건을 만족하면 다른 인격의 스킬을 즉시/턴 마지막에 사용`하는 형태가 다수 존재.
   - Trigger/Action Queue/Support가 모두 존재하지만 실제 인격 문구 전체가 자동 실행되는 수준은 아님.

5. **자원 변환/자원 전달**
   - 충전/탄환/E.G.O 자원/특수 자원 사이의 변환 및 다른 인격에게 전달하는 문구가 많다.
   - 공통 Resource primitive/runtime은 있으나 원문 전체 연결은 미완성.

6. **스킬 변경/스킬 재사용/코인 변환**
   - 원문에는 스킬 교체, 다음 턴 스킬 변경, 코인 변환, 외부 효과 재사용 제한 등이 반복됨.
   - 관련 Primitive/Runtime은 존재하지만 전체 인격 문구 실행 coverage는 낮음.

7. **확률 기믹**
   - 원문에는 50% 등 실제 조건부 확률이 존재.
   - 현재 프로젝트 정책상 고점 계산에서는 조건 충족 후 확률을 100%로 취급하지만, **조건 자체를 만족해야 한다는 부분은 유지되어야 한다.**
   - 이 부분과 실제 원문 확률 조건을 혼동하면 안 됨.

## 이번 즉시 수정
실제 원문에 존재하는 다음 표현이 Compiler에서 일부 승격되지 않는 것을 확인하여 수정했다.
- `충전 횟수가 가장 많은 아군` → `charge_max`
- `탄환을 가장 많이 보유한 아군` → `ammo_max`

기존 Runtime의 `charge_*`, `ammo_*` 값 처리 경로를 재사용한다. 새 Runtime은 만들지 않는다.

## 다음 수정 우선순위
1. Generic Target: Filter → Priority → Rank → Count
2. `자신 제외` / `상태 보유자` / `소속` 조합
3. Filtered Random
4. Priority/fallback
5. 실제 원문 Trigger → Action Queue → Effect 연결
6. Resource transfer / skill transform / cross-identity
7. Golden 기반 실제 결과 검증

## 결론
현재 계산기는 **기본적인 전투 계산과 여러 공통 기믹 축은 적절한 방향으로 반영되어 있지만, 실제 인격 원문 전체를 의미 보존 상태로 실행한다고 볼 수는 없다.**

앞으로의 완료 기준은 “Selector/Runtime이 존재한다”가 아니라 **실제 원문 문구가 계산기의 Rule → Target → Effect → State 변화 → 결과까지 보존되는지**로 한다.
