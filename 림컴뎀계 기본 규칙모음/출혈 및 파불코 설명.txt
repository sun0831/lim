현재 프로젝트에서 출혈 + 파불코(파괴 불가 코인) 관련해서 합의된 내용을 기준으로 정리하면 이거야.

1. 출혈 기본 처리
항목	현재 기준
출혈 위력	출혈 발동 시 피해 계산
출혈 Count	실제 발동 횟수만큼 감소
출혈 횟수 무한	Count 소비 없음
공격 코인	공격 스킬의 각 코인에서 출혈 판정
방어 스킬	출혈 발동 없음
코인별 처리	코인 → 출혈 → 피해 → 상태 변화 순으로 진행
출혈 Count 부족	실제 남아 있는 Count까지만 발동

즉 출혈 위력(Potency)과 출혈 횟수(Count)는 완전히 별개의 값으로 관리.

2. Clash에서의 출혈 발동 횟수

여기가 핵심.

적에게 현재 굴릴 수 있는 코인이 N개라면 해당 Clash의 출혈 발동 횟수는 그 시점의 적 활성 코인 수를 기준으로 함.

예를 들어 적이 일반 코인 3개라면:

Clash 1 → 적 코인 3개 → 출혈 3회
Clash 2 → 적 코인 2개 → 출혈 2회
Clash 3 → 적 코인 1개 → 출혈 1회

따라서 아군이 계속 Clash에서 이긴다면:

3 + 2 + 1 = 6회

의 출혈 발동.

Clash 결과에 따른 변화
아군 승리
→ 적 일반 코인 -1
→ 다음 Clash에서 적 코인 감소

무승부
→ 양쪽 코인 유지

아군 패배
→ 아군 코인 -1
→ 적 코인은 유지

그래서 Clash가 진행될수록 출혈 발동 횟수도 동적으로 변함.

3. 파불코

파불코는 일반 코인과 별도로 봐야 함.

예를 들어:

적 일반 코인 3
파불코 1

이면 최초 활성 코인 수는:

3 + 1 = 4

따라서 첫 Clash에서 출혈 관련 판정은 4개 기준.

Clash 1
→ 일반 3 + 파불코 1
→ 출혈 4회

그런데 아군이 Clash에서 승리해서 적 일반 코인을 하나 제거하면:

일반 코인 2
파불코 1

처럼 단순히 계속 3개로 유지되는 게 아니라, 파불코의 활성 여부를 별도로 처리해야 함.

현재 프로젝트에서 잡은 모델은:

파불코는 적 측에서만 의미 있는 별도 코인 이벤트로 취급하고, 일반 코인처럼 영구적으로 제거되는 코인으로 처리하지 않는다.

특히 파불코가 비활성화된 이후에는 일반 코인 수만으로 다음 Clash의 활성 코인 수를 계산.

4. 파불코와 출혈

중요한 점은 파불코를 일반 적 공격 피해로 단순 합산하면 안 됨.

현재 계산기의 관심사는 파불코가 만들어내는 출혈 관련 효과이므로:

파불코
 ↓
출혈 발동/관련 이벤트
 ↓
출혈 Count 소비

쪽으로 처리.

즉,

파불코 = 적이 나를 때리는 추가 데미지

로 단순 모델링하는 게 아님.

5. 출혈 Count 소비

예를 들어:

출혈 Count = 10
적 활성 코인 = 4

이면 해당 이벤트에서:

출혈 4회
Count 10 → 6

다음 이벤트에서 적 활성 코인이 3개라면:

출혈 3회
Count 6 → 3

그 다음 3개:

출혈 3회
Count 3 → 0

이후에는 출혈을 더 발동할 수 없음.

단,

출혈 횟수 무한

설정이면:

출혈 발동은 계속
Count 감소 = 없음

으로 처리.

6. 출혈 기반 확률 계산 모드

일반 계산과 별도로 출혈 기반 기대값 계산이 있음.

이 경우 Clash마다:

현재 상태
 ↓
P(승리)
P(무승부)
P(패배)
 ↓
각 경로 분기

를 계산.

각 Clash에서 현재 적 활성 코인 수를 E라고 하면:

Bleed Proc += E

그리고:

WIN
→ 적 일반 코인 -1

DRAW
→ 변화 없음

LOSE
→ 아군 일반 코인 -1

상태가 갱신된 뒤 다음 Clash 확률을 계산.

즉 고정적으로 3+2+1을 넣는 게 아니라 Clash 결과에 따라 출혈 발동 횟수 자체가 달라지는 구조.

7. Clash 최대 99회

현재 기준으로 Clash는:

최대 99회

까지 허용.

그리고 사용자가 확정한 규칙:

99번째 Clash는 아군 코인 상황과 관계없이 적 승리로 강제.

따라서 99번째에서 일반적인 W/T/L 확률을 다시 굴리는 것이 아님.

8. 파불코의 위치를 정확히 나누면

현재 설계상 이렇게 보는 게 제일 정확함.

적 코인 상태
│
├─ 일반 코인
│    └─ Clash 승패에 따라 감소
│
└─ 파불코
     └─ 일반 코인과 별도 상태
          ├─ 최초 활성
          ├─ 관련 출혈 이벤트
          └─ 비활성/후속 처리

따라서 enemy_coin_count 하나만 가지고 처리하면 안 되고, 최소한 내부적으로는:

enemy_normal_coins
enemy_unbreakable_coins
enemy_active_coins
unbreakable_coin_active

처럼 구분하는 게 안전함.

9. 출혈 계산에서 최종적으로 추적해야 하는 값

현재 목표 구조는:

Clash #1
├─ 적 활성 코인
├─ 출혈 발동 횟수
├─ 출혈 피해
├─ Count 변화
├─ Clash 결과
└─ 상태 변화

Clash #2
├─ 갱신된 적 코인
├─ 출혈 발동 횟수
├─ 출혈 피해
├─ Count 변화
└─ ...

그리고 최종적으로:

총 Clash 횟수
기대 Clash 횟수
총 출혈 발동 횟수
기대 출혈 발동 횟수
출혈 피해
남은 Bleed Count
99 Clash 도달 확률
최종 적 코인 상태

까지 나오는 구조.

한 줄로 정리

일반 코인은 Clash 승패에 따라 줄어들고 → 그때그때 적의 활성 코인 수가 출혈 발동 횟수를 결정하며 → 파불코는 일반 코인과 분리해서 최초 활성/비활성 및 출혈 이벤트를 따로 추적한다.

그리고 이걸 확률 모드에서는 매 Clash 상태에 포함시켜 분기하고, 마지막에 상·하위 각 5% 경로를 제거한 중앙 90%로 기대값을 산출하는 게 현재 프로젝트의 출혈 계산 방향이야.
